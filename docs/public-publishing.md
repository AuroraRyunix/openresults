# Public publishing: the contract

Agreed 2026-09-12, not yet built. OpenResults and OpenPairings are built
against this document in parallel, so **change this document first, then the
code** - a disagreement between the two repos is found here or in the hall.

## What changes

Today every publish needs the server-wide ingest token, and that token is also
the break-glass master key (`OpenResults.TournamentKeys`): present it where a
tournament key belongs and any tournament can be overwritten or deleted. It
can therefore never ship inside a desktop release.

This adds a second credential that any OpenPairings copy can obtain for
itself, scoped to the tournaments created for it, and the moderation tools
that make handing those out safe.

| Credential | Held by | May |
|---|---|---|
| Operator token (`OPENRESULTS_INGEST_TOKEN`) | the operator; hosted OpenPairings via its environment | everything, including break-glass - **unchanged** |
| Installation key | one OpenPairings installation | publish, delete, read history and registrations of tournaments minted for that installation - nothing else, never break-glass |
| Tournament key (`X-OpenResults-Key`) | one tournament, generated by the arbiter's machine | unchanged, still required on every write |

## Server switches

**Environment gate:** `OPENRESULTS_PUBLIC_PUBLISHING=enabled`. Unset (the
default, and what every self-hosted copy has after upgrading):
`/api/installations` and `/api/tournaments` 404, an installation key is never
accepted, and `GET /api/server` reports `unavailable`. A club running
OpenResults beside its own website is never opened to the public by an
upgrade.

**Runtime switches**, stored in the database, flipped from the admin panel
without a restart:

| Switch | Default | Effect |
|---|---|---|
| `registration_open` | `false` | new installations may get keys |
| `public_publishing_paused` | `false` | installation keys may not publish or mint; deleting is still allowed; operator token unaffected |

## Error bodies

Every error response, old routes and new, is:

```json
{"error": "<code>", "detail": "<an English sentence for logs>"}
```

plus the extra fields listed per code. **Clients dispatch on `error`, never on
`detail` and never on the HTTP status alone** - two different 403s mean two
different things to an arbiter. Existing codes keep their spelling:
`unauthorized`, `key_required`, `key_mismatch`, `not_found`,
`history_requires_auth`, `bad_at`.

| Code | Status | Returned by | Extra fields |
|---|---|---|---|
| `unauthorized` | 401 | any token-gated route, for a missing, malformed or unknown credential - one body for all of them, as today | |
| `installation_suspended` | 403 | mint, publish, history, registrations | |
| `installation_revoked` | 403 | every installation-key route except delete | |
| `installation_key_required` | 403 | `POST /api/tournaments` called with the operator token | |
| `not_owner` | 403 | any installation-key write or read of a slug not minted for that installation | |
| `tournament_limit` | 403 | mint | `limit` |
| `address_blocked` | 403 | registration, mint, publish | |
| `snapshot_too_large` | 413 | publish with an installation key | `limit_bytes` |
| `registration_closed` | 503 | `POST /api/installations` | |
| `publishing_paused` | 503 | mint, publish | |
| `rate_limited` | 429 | registration, mint, publish; also sets `Retry-After` | `retry_after` (seconds) |

A key that exists but is suspended or revoked gets its own 403 rather than the
anonymous 401. That tells nothing to a stranger: only the key's holder can
receive it.

## Endpoints

### `GET /api/server` - open

```json
{
  "name": "OpenResults",
  "version": "0.14.0",
  "operator": "ZeroTwo",
  "terms_url": "https://openresults.zerotwo.cloud/terms",
  "public_registration": "open",
  "public_publishing": "active"
}
```

- `operator` from `OPENRESULTS_OPERATOR_NAME`, `terms_url` from
  `OPENRESULTS_TERMS_URL`; both `null` when unset.
- `public_registration`: `open` | `closed` | `unavailable`.
- `public_publishing`: `active` | `paused` | `unavailable`.
- `Cache-Control: no-store`; never goes through the page cache.

### `POST /api/installations` - open, rate-limited

Request: `{"client": "OpenPairings", "client_version": "0.61.0"}`

201:

```json
{"installation_id": "in_7Hq2rT0bXk", "key": "orik_<43 characters>"}
```

- The key is 32 random bytes, base64url, prefixed `orik_` so it is recognisable
  in a log line or a secret scanner and cannot be confused with the operator
  token. It appears in this response once; the server stores only its SHA-256.
- Stored with the installation: client, client version, created at, created
  from (client address), status `active` | `suspended` | `revoked`, last seen
  at, last seen from. **Both addresses are nulled after 30 days.**
- Default budgets: 10 per client address per 24 hours, 200 in total per 24
  hours.

### `POST /api/tournaments` - installation key

Mints a slug bound to this installation. Request body `{}`.

201: `{"slug": "<12 characters>"}`

- 9 random bytes, base64url: exactly the shape OpenPairings' own `public_slug`
  already has, so a public-mode link looks like every link arbiters already
  share.
- **Why the server mints it.** The agreed rule was "random suffix and refuse
  existing slugs", aimed at a hostile client claiming a readable name such as
  `gent-open-2026`. OpenPairings never chooses readable slugs, so the stronger
  form costs honest clients nothing: in public mode the server picks the whole
  slug, and an installation key may touch only slugs minted for it. No name
  can be chosen, and no existing tournament - operator-owned, pre-key legacy,
  or another installation's - can be claimed.
- Starts `pending`, with no snapshot. A minted slug that has not received a
  publish within 30 days is released.
- Counts towards `tournament_limit` (default 50 tournaments that are `pending`
  or `listed`).

### Existing routes, called with an installation key

`POST /api/snapshots`, `DELETE /api/tournaments/:slug`,
`GET /api/tournaments/:slug/history`, `GET /api/tournaments/:slug/registrations`:

- The slug must be minted for this installation, otherwise `not_owner`. This
  matters most on `registrations`, the one route that returns email addresses.
- Tournament-key rules apply on top, exactly as today.
- **Default-deny.** The ingest pipeline's comment promises "a route added here
  later is authenticated by default rather than by remembering". That has to
  survive: an installation credential is refused on every ingest route unless
  that route explicitly opts in and checks ownership.
- Publish budget: 30 per minute per installation.
- Snapshot size cap for installation keys: set from measured payload sizes and
  recorded here by the server implementation. The operator token keeps today's
  parser limit.
- Delete is always allowed for the owner, even when suspended, revoked or
  paused: withdrawing your own tournament is never the harmful action.

## Tournament visibility

`status`: `pending` | `listed` | `hidden`

- Every existing tournament, and every tournament published with the operator
  token: `listed`. The migration backfills that.
- Installation-key tournaments start `pending`.

| | pending | listed | hidden |
|---|---|---|---|
| reachable at its URL | **yes** | yes | no - 404, same as an unknown slug |
| `noindex` (meta tag and `X-Robots-Tag`) | yes | no | - |
| homepage and any listing | no | yes | no |
| cross-tournament player pages and player search | **no** | yes | no |
| entry form | yes | yes | no |
| owner can publish and delete | yes | yes | delete only |

Two rows carry the design:

- **Pending is still reachable.** An arbiter's event must never wait for an
  approval on a Saturday morning. What pending withholds is the *audience*.
- **Pending stays out of player pages.** Otherwise anyone could publish a fake
  tournament full of real FIDE IDs and have invented results appear on real
  players' history pages.

A status change drops that tournament's cached pages in every locale, the same
way a publish does.

## Reports

`GET` and `POST /t/:slug/report`, open, rate-limited by client address like the
entry form.

- Fields: reason (`wrong_or_fake_results` | `personal_data` |
  `spam_or_offensive` | `other`), details (up to 2000 characters), optional
  contact email.
- Stored with the client address, nulled after 30 days.
- A "Report this page" link on every pending or listed tournament page,
  translated in `en`, `nl` and `fr`.

## Address blocks

- A single address or a CIDR range, **always with an expiry** of at most 30
  days, and a reason.
- Refuses registration, minting and publishing from that address with
  `address_blocked`. The operator token is exempt.
- Blunt by nature: a club's wifi or a mobile carrier shares one address among
  many people, so the panel shows how many installations were seen from an
  address before the block is confirmed.

## Moderation API

Context: `OpenResults.Moderation`. The admin panel calls exactly these; the
names are binding.

```elixir
settings() :: %{registration_open: boolean, public_publishing_paused: boolean}
put_setting(:registration_open | :public_publishing_paused, boolean, actor)

list_tournaments(filters)          # status, installation_id, reported?, search
get_tournament(slug)
approve(slug, actor)               # pending -> listed
hide(slug, actor)                  # -> hidden
unhide(slug, actor)                # hidden -> listed
delete(slug, actor)                # Takedown.purge/1
transfer(slug, installation_id, actor)
  # rebinds ownership and clears the stored tournament key, so the target
  # installation's next keyed publish claims it - what break-glass is used for
  # today when an arbiter's laptop dies

list_installations(filters)        # status, search
get_installation(id)
suspend(id, actor)
unsuspend(id, actor)
revoke(id, actor, hide_tournaments: boolean)

list_reports(filters)              # open | resolved
resolve_report(id, resolution, actor)

block_address(ip_or_cidr, expires_at, reason, actor)
list_blocks()
unblock(id, actor)
installations_seen_from(ip_or_cidr) :: non_neg_integer

list_actions(filters)
```

- `actor` is `%{email: String.t()}`.
- Every mutating function writes the action log: who, what, target, when.
- Break-glass uses are written to the same log, with the actor recorded as
  break-glass.

## Retention

A daily job: nulls client addresses older than 30 days (installations,
reports), releases minted slugs with no publish after 30 days, removes expired
address blocks.

## Admin panel: `/admin`

**Authentication happens at the edge, not in this app.**

- A Cloudflare Access application covers `openresults.zerotwo.cloud/admin*`,
  with Keycloak as identity provider and a policy requiring the Keycloak
  group `openresults-admin`.
- The app verifies independently, because a mistaken Access policy must never
  equal an open admin:
  - the `Cf-Access-Jwt-Assertion` header is an RS256 JWT signed by a key from
    `https://<OPENRESULTS_ADMIN_ACCESS_TEAM_DOMAIN>/cdn-cgi/access/certs`
    (cached, refetched on an unknown `kid`);
  - `aud` contains `OPENRESULTS_ADMIN_ACCESS_AUD`;
  - `iss` is `https://<team domain>`; `exp`, `nbf` and `iat` hold, with a
    small leeway;
  - the `email` claim is in `OPENRESULTS_ADMIN_EMAILS` (comma-separated,
    case-insensitive).
- **If any of those three variables is unset, every `/admin` path 404s**,
  indistinguishable from a route that does not exist.
- Session and CSRF protection on `/admin` only. The cookie is scoped
  `Path=/admin`, `Secure`, `HttpOnly`, `SameSite=Strict`. Public responses
  never gain a `Set-Cookie` from this.
- `Cache-Control: no-store` on every admin response; admin routes bypass
  `Revalidate` and the page cache.
- Destructive actions go through a confirmation page and a CSRF-checked POST.
  No JavaScript is required.
- A development bypass exists only in dev and test config; a prod boot with it
  enabled refuses to start.
- Pages: dashboard (both switches, counts, recent actions), tournaments,
  installations, reports, address blocks, action log.
- English only: it has two users. Do not wrap it in gettext.

## OpenPairings desktop

Hosted OpenPairings, and anyone configured with an operator token for their
own server, keep today's behaviour exactly.

- In local (desktop) mode the endpoint and public base default to
  `https://openresults.zerotwo.cloud`.
- **Public mode** applies when the endpoint has no operator token configured.
  When the arbiter turns publishing on for a tournament:
  1. `GET /api/server`. If `public_registration` is `unavailable`, explain that
     this server needs a token from its operator - today's message.
  2. No installation key stored: a consent dialog, once per installation,
     naming `operator` (or the host name when `operator` is null) and linking
     `terms_url` when present. Declining sends nothing and leaves publishing
     off.
  3. `POST /api/installations`; store the key. It is never shown again, never
     written into a backup or export, and never carried by a restore onto
     another machine - the same custody rules as a tournament's
     `openresults_key`.
  4. `POST /api/tournaments`; the minted slug becomes the tournament's
     `public_slug`. **Until that has succeeded, no public link or QR code is
     shown or printed for the tournament**, because a link printed with a
     local slug would be dead.
  5. Publish as today.
- Rotating the public link in public mode mints a new slug and deletes the
  copy published under the old one.
- Error handling dispatches on `error`:

| Code | What the arbiter sees | Queue |
|---|---|---|
| `rate_limited` | nothing unless it persists | back off at least `retry_after` |
| `publishing_paused` | amber: the results site has paused publishing | keep, retry later |
| `installation_suspended` | red: contact the operator | keep |
| `installation_revoked` | red: this installation's key is no longer accepted | stop |
| `tournament_limit` | red, with the limit | stop for that tournament |
| `snapshot_too_large` | red, with the limit | stop for that tournament |
| `not_owner` | red: a different installation owns this tournament | stop for that tournament |
| `registration_closed` | the results site is not accepting new installations right now | nothing sent |
| `address_blocked` | red: contact the operator | stop |

- **Never re-register silently.** A 401 or `installation_revoked` offers a
  deliberate "Register again" button, which shows the consent dialog again.
  Silent re-registration would turn every revocation into a one-second
  inconvenience.

## Defaults

Defaults live in config; each may be overridden from the environment.

| Setting | Default | Variable |
|---|---|---|
| public publishing exists | off | `OPENRESULTS_PUBLIC_PUBLISHING=enabled` |
| operator name shown in the consent dialog | none | `OPENRESULTS_OPERATOR_NAME` |
| terms page | none | `OPENRESULTS_TERMS_URL` |
| registrations per address per 24 h | 10 | `OPENRESULTS_REGISTRATIONS_PER_ADDRESS` |
| registrations per 24 h | 200 | `OPENRESULTS_REGISTRATIONS_PER_DAY` |
| publishes per installation per minute | 30 | `OPENRESULTS_INSTALLATION_PUBLISHES_PER_MINUTE` |
| pending + listed tournaments per installation | 50 | `OPENRESULTS_INSTALLATION_MAX_TOURNAMENTS` |
| snapshot size for installation keys | measured, recorded above | `OPENRESULTS_INSTALLATION_MAX_SNAPSHOT_BYTES` |
| Access team domain | none | `OPENRESULTS_ADMIN_ACCESS_TEAM_DOMAIN` |
| Access application audience | none | `OPENRESULTS_ADMIN_ACCESS_AUD` |
| admin emails | none | `OPENRESULTS_ADMIN_EMAILS` |

## Before switching it on

1. The Cloudflare Access application and the Keycloak group exist, and
   `/admin` loads for an admin and refuses everyone else.
2. A terms and acceptable-use page with a takedown contact exists and
   `OPENRESULTS_TERMS_URL` points at it.
3. `OPENRESULTS_PUBLIC_PUBLISHING=enabled`, then `registration_open` flipped
   in the panel.
